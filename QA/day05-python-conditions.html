Сравнения и True/False

около 20 минут

До сегодняшнего дня твои программы шли одной дорогой сверху вниз. Сегодня появится развилка: код начнёт проверять условие и выбирать, что делать дальше.

Всё начинается со сравнения. Когда Python что-то сравнивает, он отвечает одним из двух слов: True или False. Это тип bool, ты его уже видела на третьем дне.

# попробуй выполнить это построчно
print(5 > 3)      # True
print(5 < 3)      # False
print(5 == 5)     # True
print(5 != 5)     # False
ОператорЗначениеПример
==равноage == 18
!=не равноname != ""
>большеprice > 1000
<меньшеcount < 10
>=больше или равноage >= 18
<=меньше или равноage <= 65
Одно равно и два равно — разные вещи

= кладёт значение в переменную. == спрашивает, равны ли两 значения.

Это ошибка номер один у всех новичков, и Python на ней остановит программу.

age = 18        # присвоила: теперь age это 18
age == 18       # спросила: age равен 18? → True

Сравнивать можно и строки. Тогда == проверяет полное совпадение, включая регистр и пробелы:

print("Анна" == "Анна")    # True
print("Анна" == "анна")    # False — разный регистр
print("Анна" == "Анна ")   # False — лишний пробел
Где ты это встретишь как тестировщик

Ровно на этих трёх строчках ломается масса форм авторизации. Система не обрезает пробелы по краям, пользователь копирует логин с пробелом в конце — и получает «неверный логин». Проверка на пробелы в начале и конце поля входит в любой чек-лист.

В тетрадь

  • Таблица из шести операторов сравнения
  • Крупно: = присвоить, == сравнить
  • Результат сравнения — всегда True или False

if и else

около 25 минут

Конструкция if говорит: если условие верно — выполни этот кусок кода. Если нет — пропусти.

age = 20

if age >= 18:
    print("Доступ разрешён")

Разберём по частям, потому что здесь три вещи, которых раньше не было.

Двоеточие в конце строки

После условия обязательно ставится :. Оно означает «дальше идёт блок кода, который относится к этому условию». Забыла двоеточие — получишь SyntaxError.

Отступ

Строки внутри условия сдвинуты вправо на четыре пробела. Именно отступ показывает Python, что относится к условию, а что нет.

В большинстве языков для этого используют фигурные скобки. В Python их роль играют отступы — поэтому они не оформление, а часть синтаксиса. PyCharm ставит их сам после двоеточия и Enter.

else — что делать в остальных случаях

Выполняется, когда условие оказалось ложным.

age = 15

if age >= 18:
    print("Доступ разрешён")
else:
    print("Доступ запрещён")

Обрати внимание: else стоит на том же уровне, что и if, без отступа. Условия у него нет — только двоеточие.

Что видно по отступам

age = 15

if age >= 18:
    print("Внутри условия")   # выполнится только если age >= 18
print("Снаружи условия")       # выполнится всегда

Одна строка сдвинута, вторая нет — и они ведут себя по-разному. Сдвинутая принадлежит условию, несдвинутая живёт сама по себе.

IndentationError

Самая частая ошибка этого дня. Означает проблему с отступами: строка сдвинута не туда или сдвиг неровный.

Чаще всего причина — смешение пробелов и табов. Внешне одинаково, для Python по-разному. Нажми Ctrl+Alt+L, PyCharm выровняет всё сам.

Связь с тем, что ты учила вчера

Строка if age >= 18 — это ровно тот случай, который разбирался в теории. Стоит написать > вместо >=, и восемнадцатилетний не пройдёт. Граничное значение, один символ, реальный баг.

Когда ты будешь тестировать чужую форму, помни: по ту сторону лежит примерно такая же строчка.

elif: больше двух вариантов

около 25 минут

if и else дают две дороги. Когда вариантов больше, между ними вставляют elif — сокращение от «else if», то есть «иначе, если».

score = 75

if score >= 90:
    print("Отлично")
elif score >= 75:
    print("Хорошо")
elif score >= 60:
    print("Удовлетворительно")
else:
    print("Неудовлетворительно")

Главное правило: проверка идёт сверху вниз и останавливается

Python проверяет условия по очереди. Как только одно оказалось истинным — выполняет его блок и выходит из всей конструкции. Остальные ветки не проверяются даже если тоже подходят.

В примере выше score = 75 подходит и под >= 75, и под >= 60. Выведется только «Хорошо», потому что оно стоит выше.

Отсюда — ловушка с порядком условий

Переставим ветки местами:

score = 95

if score >= 60:
    print("Удовлетворительно")
elif score >= 90:
    print("Отлично")

Выведется «Удовлетворительно». Девяносто пять подошло под первое условие, и до второго дело не дошло. Код формально рабочий, ошибок нет, результат неверный.

Правило: при проверке диапазонов условия идут от самого строгого к самому мягкому.

Почему это важно именно тебе

Такой баг невозможно найти, глядя на код бегло — он выглядит правильным. Находится он только проверкой граничных значений: подставить 95, 90, 89, 75, 60, 59 и сравнить с ожидаемым.

Это и есть тест-дизайн, который ты будешь разбирать на седьмой день. Здесь ты видишь его с другой стороны — со стороны кода, в котором живёт баг.

В тетрадь

  • Шаблон цепочки: if — elif — elif — else
  • Крупно: проверка идёт сверху вниз и останавливается на первом совпадении
  • Правило порядка: от строгого условия к мягкому
  • Пример с переставленными ветками — он важнее остального

Логические операторы

около 25 минут

Когда условие одно — хватает сравнения. Когда их несколько, их соединяют словами and, or, not.

and — и

Истинно, только если истинны оба условия.

age = 25
has_passport = True

if age >= 18 and has_passport:
    print("Можно оформить договор")
or — или

Истинно, если истинно хотя бы одно условие.

is_admin = False
is_owner = True

if is_admin or is_owner:
    print("Можно редактировать")
not — не

Переворачивает значение: истину делает ложью и наоборот.

is_blocked = False

if not is_blocked:
    print("Вход разрешён")

Таблица истинности

ABA and BA or B
TrueTrueTrueTrue
TrueFalseFalseTrue
FalseTrueFalseTrue
FalseFalseFalseFalse

Эта таблица понадобится не только в коде: на ней строится техника тест-дизайна «таблица решений», которую ты будешь разбирать на девятый день.

Диапазон двумя способами

# длинный способ
if age >= 18 and age <= 65:
    print("Подходит")

# короткий, так пишут в Python
if 18 <= age <= 65:
    print("Подходит")
Частая ошибка с or

Так написать нельзя:

if name == "Анна" or "Мария":

Python прочитает это как два независимых куска: «name равен Анне» или «строка Мария». Непустая строка считается истиной, поэтому условие будет верным всегда, при любом имени.

Правильно — повторить сравнение полностью:

if name == "Анна" or name == "Мария":

В тетрадь

  • Три оператора с расшифровкой одним словом
  • Таблица истинности целиком
  • Короткая запись диапазона 18 <= age <= 65
  • Ошибка с or "Мария" — почему условие всегда истинно

Шесть задач

около 70 минут

Каждая — отдельный файл в папке python/day05/. Пиши руками, не копированием. Если задача не идёт больше двадцати минут — переходи к следующей и возвращайся потом.

1. Проверка возраста

age_check.py

Спрашивает возраст. Если 18 или больше — «Доступ разрешён», иначе — «Доступ запрещён».

Обязательно проверь работу на трёх значениях: 17, 18, 19. Это граничные значения, и именно они ловят ошибку со знаком.

2. Чётное или нечётное

even_odd.py

Спрашивает число и сообщает, чётное оно или нет.

Подсказка: число чётное, если остаток от деления на 2 равен нулю. Оператор остатка — %, он был на третьем дне.

3. Вход в систему

login.py

Хранит правильные логин и пароль в переменных. Спрашивает у пользователя логин и пароль. Если совпали оба — «Вход выполнен», иначе — «Неверный логин или пароль».

Подумай, почему в реальных системах не пишут отдельно «неверный логин» и «неверный пароль». Ответ связан с безопасностью.

4. Оценка по баллам

grade.py

Спрашивает балл от 0 до 100 и выводит оценку: 90 и выше — отлично, 75–89 — хорошо, 60–74 — удовлетворительно, ниже 60 — неудовлетворительно.

Проверь на граничных значениях: 89, 90, 74, 75, 59, 60. Все шесть должны дать ожидаемый результат.

5. Скидка по сумме заказа

discount_levels.py

Спрашивает сумму заказа. До 1000 — скидки нет, от 1000 до 4999 — 5%, от 5000 до 9999 — 10%, от 10000 — 15%. Выводит процент скидки, размер скидки и итоговую сумму.

6. Валидатор поля

validator.py

Спрашивает имя пользователя и проверяет по правилам: не пустое, не короче трёх символов, не длиннее двадцати. Выводит либо «Имя корректно», либо конкретную причину отказа.

Подсказка: длина строки — len(name). Пустая строка проверяется как name == "".

Это задача с точки зрения тестировщика: ты пишешь то, что обычно проверяешь с другой стороны. Прогони её на пустой строке, на двух символах, на трёх, на двадцати, на двадцати одном.

Проверка: читаем код

около 25 минут

Восемь вопросов на чтение кода. Отвечай в голове, прежде чем выбирать вариант — не запускай в PyCharm. Умение предсказать поведение кода по тексту важнее умения его написать.

1Что выведет этот код?

age = 18

if age > 18:
    print("Взрослый")
else:
    print("Несовершеннолетний")
Восемнадцать не больше восемнадцати, поэтому условие ложно и срабатывает else. Классический баг с граничным значением: нужен был оператор >=. Такой код выглядит правильным и ломается ровно на одном значении.

2Что выведет этот код?

score = 95

if score >= 60:
    print("Удовлетворительно")
elif score >= 90:
    print("Отлично")
Проверка идёт сверху вниз и останавливается на первом истинном условии. 95 подошло под >= 60, и до второй ветки дело не дошло. Условия для диапазонов ставят от строгого к мягкому.

3Что выведет этот код?

age = 15

if age >= 18:
    print("Первая")
print("Вторая")
Строка «Первая» сдвинута — она внутри условия и не выполнится. Строка «Вторая» без отступа, она живёт сама по себе и выполняется всегда. Отступ решает, что кому принадлежит.

4В чём ошибка?

name = "Пётр"

if name == "Анна" or "Мария":
    print("Своя")
Python читает это как два независимых условия: «name равен Анне» или «строка Мария». Вторая часть — просто непустая строка, а она всегда истинна. В результате «Своя» выведется для любого имени. Нужно повторить сравнение: name == "Анна" or name == "Мария".

5Пользователь ввёл 25. Что произойдёт?

age = input("Возраст: ")

if age >= 18:
    print("Ок")
input() всегда возвращает строку, а сравнивать строку с числом Python не умеет. Нужно age = int(input("Возраст: ")). Та самая ловушка третьего дня — теперь она проявляется в условиях.

6Что выведет этот код?

is_admin = False
is_owner = False

if not is_admin and not is_owner:
    print("Нет прав")
else:
    print("Есть права")
not False даёт True для обеих переменных. True and True = True, поэтому выполняется первая ветка. Разбирай такие выражения по шагам, подставляя значения — именно так их и читают.

7Какое значение НЕ пройдёт эту проверку, хотя должно по условию задачи «возраст от 18 до 65 включительно»?

if 18 < age <= 65:
    print("Подходит")
Слева стоит строгое < вместо <=, поэтому ровно 18 не проходит. Верхняя граница задана правильно. Один символ — и целая категория пользователей отсекается. Такие баги ловятся только проверкой границ.

8Что выведет этот код?

password = "Qwerty123"
entered = "qwerty123"

if password == entered:
    print("Вход выполнен")
else:
    print("Неверный пароль")
Сравнение строк учитывает регистр: «Q» и «q» — разные символы. Для паролей это правильное поведение, а вот для логина или email обычно нет: там регистр приводят к одному виду. Проверка «работает ли вход с логином в другом регистре» есть в любом чек-листе на авторизацию.
