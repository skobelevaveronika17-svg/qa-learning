Простыми словами

Чтобы поработать с файлом, его открывают командой open и говорят, зачем: читать, писать заново или дописывать в конец. Перепутать эти режимы — самая частая ошибка: один из них молча стирает файл.

open(имя, режим)
Открыть файл. Возвращает объект файла — обычно его называют f.
Режим "r" — читать
Только чтение. Если режим не указан, это он. Файла нет — ошибка.
Режим "w" — писать заново
Открывает файл для записи и сразу стирает всё, что в нём было. Файла нет — создаёт.
Режим "a" — дописать
От английского append. Новый текст добавляется в конец, старый остаётся.
\n — перенос строки
write пишет ровно то, что дали. Хочешь новую строку — добавь "\n" сама, иначе всё сольётся в одну строку.
with open(...) as f:
Открыть файл на время блока. Когда блок закончился, файл закрывается сам — даже если внутри случилась ошибка. Без with файл нужно закрывать вручную: f.close().

Файлы в Python

35 минут · четыре части

1. Режимы — главное, что нужно помнить

[Бумага] Три режима
РежимЗачемФайла нетФайл есть
"r"Читать. По умолчаниюОшибка FileNotFoundErrorЧитает с начала
"w"Писать зановоСоздаётСтирает всё и пишет с нуля
"a"Дописать в конецСоздаётСтарое остаётся, новое — в конец

Запоминалка: w — wipe, стереть. a — add, добавить.

2. Как читать

Пусть в файле users.txt три строки:

anna@test.ru
ivan@test.ru
olga@test.ru
СпособЧто получаемКогда
f.read()Весь файл одной строкой: "anna@test.ru\nivan@test.ru\nolga@test.ru\n"Файл маленький, нужен целиком
for line in f:По одной строке за проход. Каждая с \n на конце: "anna@test.ru\n"Почти всегда. Особенно — большие файлы, логи

Разобранный пример — построчное чтение

with open("users.txt", encoding="utf-8") as f:
    for line in f:
        email = line.strip()
        if email == "":
            continue
        print(email, len(email))
Проходlineemail после stripПечать
1"anna@test.ru\n""anna@test.ru"anna@test.ru 12
2"ivan@test.ru\n""ivan@test.ru"ivan@test.ru 12
3"olga@test.ru\n""olga@test.ru"olga@test.ru 12
Ловушка: невидимый \n

Без strip() длина была бы 13, а не 12, и сравнение line == "anna@test.ru" давало бы False. Это классический баг тестов, которые читают данные из файла: «строки выглядят одинаково, а не равны». Правило: каждую строку из файла сразу strip().

Проверка на пустую строку нужна для пустых строк в файле, особенно последней — её часто оставляют случайно.

3. Как писать

with open("report.txt", "w", encoding="utf-8") as f:
    f.write("Строка 1\n")
    f.write("Строка 2\n")

write принимает только строку. Число сначала превращают: str(len(results)) или через f-строку.

[Бумага] Рецепт, который подходит почти всегда
with open(путь, режим, encoding="utf-8") as f:
  1. Всегда with — закроется сам.
  2. Всегда encoding="utf-8" — русский текст не сломается на другом компьютере.
  3. Режим осознанно: читать — без режима, заново — "w", дописать — "a".
  4. При записи — "\n" сама. При чтении — strip() сама.

4. Где ищется файл — путь

Когда ты пишешь open("settings.txt"), Python ищет файл в текущей папке терминала, а не рядом со скриптом. Запустишь из PyCharm кнопкой Run — найдёт. Запустишь из терминала, стоя в корне репозитория, — FileNotFoundError. Вчера у тебя это было: test_users.json появлялся то в одной папке, то в другой.

Надёжный способ — строить путь от файла скрипта:

from pathlib import Path

BASE = Path(__file__).parent          # папка, где лежит этот .py

with open(BASE / "settings.txt", encoding="utf-8") as f:
    ...
КусокЧто это
__file__Путь к текущему файлу .py, Python знает его сам. Например C:\projects\qa-learning\python\generator\config.py
Path(...).parentПапка, в которой лежит файл: …\python\generator
BASE / "settings.txt"Склеить путь: …\python\generator\settings.txt. Да, через знак деления — pathlib так устроен
Зачем это тестировщику
  1. Тестовые данные — из CSV, JSON, txt. Это data-driven, который ты делаешь с дня 19.
  2. Настройки — адрес стенда, логин, таймауты. Их не пишут в код: стенд поменялся — поменяли файл, код не трогали.
  3. Логи — читаешь построчно и ищешь строки с ERROR после прогона.
  4. Отчёты — Allure, который будет на этапе pytest, тоже пишет файлы.
Формулировка для собеседования — выучи вслух

Вопрос: «Чем отличаются режимы w и a?»

«Оба открывают файл на запись и создают его, если файла нет. Но w сразу стирает содержимое, а a дописывает в конец. Открываю файлы через with — тогда файл закроется сам, даже если внутри будет ошибка, — и всегда указываю encoding utf-8.»

Чек-лист: загрузка аватара

30 минут · ручное тестирование файлов · подготовка к контрольной по границам

Раз сегодня про файлы — тестируем функцию, которая принимает файл от пользователя. Это одно из самых частых заданий на собеседовании.

Требование
  1. Пользователь загружает аватар в личном кабинете.
  2. Форматы: JPG и PNG.
  3. Размер файла: до 5 МБ.
  4. Размер картинки: не меньше 200 × 200 пикселей.
  5. При ошибке показывается текст под кнопкой загрузки. Тексты — уточнить у аналитика.

Что сделать — по шагам

Файл manual/day24-avatar-checklist.md.

  1. Классы эквивалентности по формату — минимум шесть. Подумай не только «JPG, PNG, GIF»: а файл с расширением .jpg, который на самом деле текстовый документ? А .JPG большими буквами? А .jpeg? А файл без расширения? Для каждого — «валидный / невалидный / уточнить».
  2. Граничные значения размера файла. Граница — 5 МБ. Трёхточечный подход: чуть меньше, ровно, чуть больше. Но сначала вопрос: 5 МБ — это 5 000 000 байт или 5 242 880 (5 × 1024 × 1024)? Это разные числа, и программист мог понять так, а аналитик иначе. Не выбирай сама — запиши вопрос аналитику и распиши границы для обоих вариантов.
  3. Граничные значения размера картинки. Граница 200 × 200. Здесь два измерения: что если ширина 200, а высота 199? Распиши минимум пять проверок: обе стороны на границе, одна сторона на 1 меньше, другая на 1 меньше, обе больше, обе меньше.
  4. Особые случаи — минимум четыре: файл 0 байт; имя файла на русском и с пробелами; очень длинное имя файла; загрузка второго аватара поверх первого.
  5. Вопросы аналитику — в конце файла, пронумерованные, с вариантами ответа. Минимум три. Один — про МБ из шага 2.

Формат строки чек-листа, как в дне 10:

| № | Проверка | Данные | Ожидание |
|---|---|---|---|
| 1 | Граница размера изнутри | файл ровно 200 × 200 px, PNG, 1 МБ | загружается |
Не перепутай

В строках про размер файла держи формат валидным — PNG, а в строках про формат держи размер нормальным — 1 МБ. Ломается только одно правило за раз, как в тест-кейсах.

Готово, когда минимум 20 строк: 6+ про формат, 3–6 про размер файла, 5+ про размер картинки, 4+ особых, и 3+ вопроса аналитику с вариантами.

Шаг 2 · config.py с функцией load_settings · 25 минут

Что сделать. Новый модуль config.py в той же папке. В нём функция load_settings(path): читает файл построчно и возвращает словарь.

Это почти parse_cookies из дня 22, только строки берутся из файла, а не режутся по "; ".

  1. В начале файла: 
    from pathlib import Path

BASE = Path(__file__).parent
  2. Функция: пустой словарь, потом with open(path, encoding="utf-8") as f: и цикл for line in f:.
  3. В цикле, по порядку:
    • line = line.strip() — убрать \n;
    • если строка пустая или начинается с # — continue, пропустить;
    • разрезать по "=" на две части — со вторым аргументом 1, как в звёздочке дня 22;
    • положить в словарь: часть [0] — ключ, часть [1] — значение.
  4. return словаря — после цикла и после блока with, без отступа внутри них. Помнишь вчерашнее «Итого»?
  5. Проверки внизу, спрятанные под if __name__ == "__main__":: 
    if __name__ == "__main__":
    s = load_settings(BASE / "settings.txt")
    print(s == {"domain": "test.ru", "min_length": "8", "max_length": "20"})
    print(int(s["min_length"]) == 8)

Заметь: в словаре "8" — строка, а не число. Из файла всё читается строками, как и из split. Поэтому во второй проверке int(...).

Проверка. Run для config.py — два True. Если первый False — напечатай print(s) и сравни глазами: скорее всего, в ключе или значении остался пробел или \n, или в словарь попал комментарий.

Шаг 4 · Отчёт в файл · 10 минут

Применяем охоту. Кроме печати на экран, запиши тот же результат в report.txt в папке генератора: строка на каждого пользователя и итог последней строкой.

  1. До цикла проверки — пустой список lines = [].
