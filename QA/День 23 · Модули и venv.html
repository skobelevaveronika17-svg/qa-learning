Простыми словами

Любой файл .py — это модуль. Из одного модуля можно взять функцию в другой одной строкой import. Кроме твоих файлов, есть чужие модули: часть встроена в Python (например, json), часть надо скачать командой pip install. А скачивать их принято не «в компьютер вообще», а в отдельную папку для каждого проекта — виртуальное окружение.

Модуль
Файл с кодом на Python. Имя модуля — имя файла без .py: файл checks.py — модуль checks.
import
Команда «подключи модуль». import json — подключить весь модуль. from checks import check_email — взять из модуля одну функцию.
Стандартная библиотека
Модули, которые уже есть в Python: json, random, datetime. Скачивать не нужно.
pip
Программа, которая скачивает чужие модули из интернета. pip install requests — скачать модуль requests.
Виртуальное окружение, venv
Отдельная папка проекта (у тебя — .venv), куда pip ставит модули. Видно по (.venv) в начале строки терминала. Если окружение не включено, pip ставит модули в другое место, и проект их не видит.
requirements.txt
Список модулей, которые нужны проекту, с версиями. Коллега скачивает репозиторий, ставит всё одной командой — и код у него запускается.

Модули, pip и окружение

35 минут · пять частей

1. Модуль — это просто файл. Пример на двух файлах

В одной папке лежат два файла.

greet.py

модуль с функцией

main.py

файл, который запускаем

# greet.py
print("greet загружен")

def hello(name):
    return f"Привет, {name}!"
# main.py
import greet
from greet import hello

print(greet.hello("Анна"))
print(hello("Вероника"))

Запускаем python main.py. Вывод:

greet загружен
Привет, Анна!
Привет, Вероника!
СтрокаЧто происходит
import greetPython находит файл greet.py рядом и выполняет его целиком — поэтому напечаталось «greet загружен». Функции из него доступны через точку: greet.hello
from greet import helloБерём одну функцию по имени. Теперь её можно вызывать без greet.. Повторно файл не выполняется: Python подключает каждый модуль один раз
[Бумага] Три способа импорта
ЗаписьКак потом вызыватьКогда удобно
import jsonjson.dumps(...)Модуль большой, нужно много функций. Сразу видно, откуда функция
from checks import check_emailcheck_email(...)Нужны одна-две функции
import datetime as dtdt.date.today()Длинное имя модуля. as — короткое прозвище

Импорты пишут в самом начале файла: сначала модули Python, потом свои.

2. if __name__ == "__main__"

Проблема: в greet.py хочется оставить проверки функций. Но тогда при каждом import greet они будут выполняться и печатать в чужой вывод.

Решение — спрятать проверки под условие:

# greet.py
def hello(name):
    return f"Привет, {name}!"

if __name__ == "__main__":
    print(hello("тест") == "Привет, тест!")
Простыми словами

У каждого модуля есть скрытая переменная __name__. Если файл запустили напрямую — python greet.py, — в ней лежит "__main__", и проверки выполняются. Если файл подключили через import — в ней лежит "greet", и проверки пропускаются. Одна строка — и файл работает и как модуль, и как отдельная программа.

3. Как называть модули

[Бумага] Четыре правила имени файла
  1. Маленькие латинские буквы, цифры, подчёркивание: check_email.py.
  2. Без пробелов и дефисов: make password.py и make-password.py не подключить.
  3. Не с цифры: 22_cookies.py не подключить, day22_cookies.py — можно.
  4. Не как модули Python: json.py, random.py, email.py перекроют настоящие — блок 4 охоты.

4. pip и requirements.txt

[Бумага] Пять команд pip
КомандаЧто делает
pip install requestsСкачать и поставить модуль
pip listПоказать, что установлено в окружении
pip freeze > requirements.txtЗаписать список установленного с версиями в файл. Знак > значит «вывод не на экран, а в файл»
pip install -r requirements.txtПоставить всё по списку из файла. -r — «из файла»
pip uninstall requestУдалить модуль

Как выглядит requirements.txt — просто строки «имя==версия»:

requests==2.32.3
pytest==8.3.3

Почему версии важны: в новой версии модуля функция может измениться. С записанной версией у всей команды и на сервере CI стоит одно и то же — тест не упадёт «только у меня».

5. Виртуальное окружение

Зачем. Проект А работает с pytest 7, проект Б — с pytest 8. Если ставить всё в один общий Python, проекты начнут мешать друг другу. Окружение — своя папка с модулями для каждого проекта.

[Бумага] Окружение — три команды для Windows
ЧтоКоманда
Создать окружение в папке .venvpython -m venv .venv
Включить (PowerShell).venv\Scripts\Activate.ps1
Выключитьdeactivate

Окружение включено, если в начале строки терминала есть (.venv). У тебя PyCharm делает это сам — на скриншотах дня 21 строка начинается с (.venv) PS C:\projects\qa-learning>.

Папка .venv в репозиторий не попадает — она в .gitignore, ты проверяла в дне 21. В репозиторий идёт только requirements.txt, а окружение каждый создаёт у себя.

Если PowerShell пишет «выполнение сценариев отключено»

Это защита Windows. Не меняй настройки системы, просто работай в терминале PyCharm — там окружение включается само.

Формулировка для собеседования — выучи вслух

Вопрос: «Как вы готовите окружение для запуска автотестов?»

«Для каждого проекта создаю виртуальное окружение через venv, чтобы зависимости не пересекались с другими проектами. Ставлю пакеты через pip, а список с версиями фиксирую в requirements.txt и коммичу — тогда коллеги и CI ставят то же самое одной командой pip install -r. Саму папку окружения в репозиторий не кладу.»

Окружение и порядок в репозитории

30 минут · в терминале PyCharm, в папке qa-learning

Перед началом
  1. git status — должно быть nothing to commit, working tree clean. Если нет — сначала закоммить.
  2. В начале строки терминала есть (.venv). Если нет — закрой и открой терминал в PyCharm.

Часть 1 · Что стоит в окружении · 10 минут

  1. Выполни pip list. Запиши в файл notes/day23-venv.md, сколько пакетов в списке и какие. Скорее всего, их два-три: pip и ещё что-то служебное. Это значит, окружение чистое.
  2. Проверь, какой Python запускается: 
    python -c "import sys; print(sys.executable)"
    В ответе должен быть путь с .venv, например C:\projects\qa-learning\.venv\Scripts\python.exe. Запиши, что вышло. Если пути с .venv нет — окружение не включено, напиши мне.
  3. Поставь модуль, который понадобится нам для тестирования API: 
    pip install requests
    В конце будет Successfully installed requests-… и ещё несколько пакетов — это то, без чего requests не работает. Запиши номер версии requests.
  4. Ещё раз pip list. Запиши, сколько пакетов стало и почему больше, чем один.

Часть 2 · requirements.txt · 10 минут

  1. Запиши список в файл: 
    pip freeze > requirements.txt
    В корне репозитория появится файл requirements.txt. Открой его в PyCharm и посмотри: строки «имя==версия».
  2. Проверь, что Git видит новый файл, а не папку .venv: 
    git status
    Должен быть requirements.txt в Untracked files и ничего из .venv.
  3. Закоммить: 
    git add requirements.txt
git commit -m "Добавлен requirements.txt"

Часть 3 · Переименовать файл с пробелом · 10 минут

Зачем. Блок 5 охоты: файл с пробелом в имени нельзя подключить через import. А во втором заходе пароли станут модулем.

  1. Переименуй через Git — тогда он поймёт, что это тот же файл, а не удалённый и новый. Имя в кавычках, потому что в нём пробел: 
    git mv "python/day20/make_password v2.py" python/day20/make_password_v2.py
  2. git status — должно быть renamed: python/day20/make_password v2.py -> python/day20/make_password_v2.py.
  3. Найди в репозитории другие файлы с пробелами, дефисами или цифрой в начале имени — в папке python/. Если есть — переименуй так же. Если нет — так и запиши.
  4. Закоммить и отправь: 
    git commit -m "Имена файлов без пробелов"
git push
Готово, когда на GitHub есть requirements.txt с requests, нет файлов с пробелами в python/, а в notes/day23-venv.md записаны результаты частей 1 и 2.

Сейчас код генератора разбросан по файлам дней 19–21, и в каждом что-то скопировано из предыдущего. Собираем его в один небольшой проект из трёх файлов. Это мини-проект 1, финальная версия.

Делает тестовые данные: make_email, make_password, make_bad_email

checks.py

Проверяет данные, как форма: has_digit, has_upper, check_password, check_email

Запускаемый файл: собирает пользователей, пишет JSON, прогоняет проверки, печатает итог

Шаг 1 · data.py · 15 минут

Что сделать. Перенеси в data.py три функции, ничего не меняя внутри:

  1. make_email — из любого дня 19–21.
  2. make_password — версию v2 из python/day20/make_password_v2.py (с None для маленьких длин).
  3. make_bad_email — из python/day21_emails.py.
  4. Внизу файла — проверки, спрятанные под if __name__ == "__main__":. Возьми по одной-две из прошлых дней, например:

Шаг 3 · run.py · 25 минут

Что сделать. Это главный файл. В нём нет ни одной функции из data.py и checks.py — только импорт.

  1. Импорты в начале файла, сначала модуль Python, потом свои:

  3. Запись и чтение JSON — по рецепту дня 19, файл test_users.json.
  4. Цикл проверки по прочитанным пользователям, как в днях 20–22: строка на каждого (email и PASSED или FAILED с тем, что вернулось) и один итог словарём-счётчиком после цикла.

  2. Посчитай длину и запиши в тестовых данных так: пароль Xxxxxx1 — 7 символов: X, x, x, x, x, x, 1 — по буквам, чтобы проверяющий сразу видел, что их 7. Используй свой пароль, не этот пример.
  3. Email — anna@gmail.com.
  4. Шаги: ввести email, ввести пароль, нажать «Войти».
  5. Ожидаемый результат: какое сообщение (дословно), где, и ушёл ли запрос на сервер. Вспомни правило 4.1.

  7. Постусловие: подумай сама, по TC-011.

TC-013 · Пароль из 20 символов — верхняя граница, успешный вход

Этот кейс сложнее, и в нём главное — предусловие. Чтобы проверить, что пароль из 20 символов принимается, нужен пользователь, у которого настоящий пароль ровно 20 символов. С паролем Анны Anna1234 это не проверить: ты введёшь 20 символов — и получишь «Неверный email или пароль», потому что пароль не её.

  1. Предусловие. Опиши пользователя: email (придумай другой, не anna, например max20@gmail.com), пароль ровно из 20 символов, с цифрой и заглавной, не заблокирован, неверных попыток 0. Пользователь не авторизован.

  3. Подсказка, как получить пароль ровно из 20 символов: у тебя есть генератор. make_password(20) вернёт пароль нужной длины с цифрой и заглавной — используй его.
  4. Шаги: ввести email, ввести пароль, нажать «Войти».
  5. Ожидаемый результат: что видит пользователь при успешном входе. Посмотри, как это написано в твоём TC-001, и напиши так же.
  6. Постусловие: пользователь в кабинете — что сделать, чтобы не мешать следующим кейсам?
