Как читать ошибку

Expecting property name enclosed in double quotes: line 3 column 3 — «ожидал имя свойства в двойных кавычках, строка 2, столбец 3». Строки считаются от открывающих трёх кавычек. Первая строка после них пустая, поэтому номер в ошибке на один больше, чем в самом файле: «line 3» — это вторая строка файла. Подсказка обычно точная: что Python ждал и где.

JSON, и как разбить программу на функции

40 минут

Простыми словами

JSON — это текст, записанный по строгим правилам, который выглядит почти как словари и списки Python. Python умеет превращать JSON в словари и обратно одной командой. Поэтому ответ сервера или файл с данными становится обычным словарём, а с ним ты уже работать умеешь.

Как выглядит JSON

{
  "email": "anna@test.ru",
  "age": 25,
  "active": true,
  "roles": ["user", "tester"],
  "manager": null
}

Объект в фигурных скобках — словарь. Массив в квадратных — список. Внутри — строки, числа, true/false, null и другие объекты и массивы.

[Бумага] Пять правил, на которых падают
  1. Ключи и строки — только в двойных кавычках.
  2. true, false, null — с маленькой буквы.
  3. Никаких запятых после последнего элемента.
  4. Никаких комментариев.
  5. Между элементами — запятая всегда.

Как разбить программу на функции

Простыми словами

Одна функция — одно дело. Если функцию трудно назвать одним глаголом — она делает два дела, её надо разделить. Функции вызывают друг друга, как в твоём check_password, который вызывает has_digit и has_upper.

def make_email(name, domain="test.ru"):     # делает почту
    return f"{name}@{domain}"

def make_user(name, password):              # собирает пользователя — вызывает make_email
    return {"email": make_email(name), "password": password}

print(make_user("anna", "Anna1234"))
# {'email': 'anna@test.ru', 'password': 'Anna1234'}

Каждую маленькую функцию легко проверить отдельно. Если сломалось — сразу видно где.

Зачем тестировщику генератор

Тестовые данные руками — это опечатки, как в охоте, и забытые случаи. Генератор создаёт их по правилам, без ошибок, сколько угодно. А если в каждой записи хранить ещё и ожидаемый результат, одна функция проверит все записи разом. Это называется тестированием на основе данных — data-driven, и pytest умеет это из коробки.

Шаг 2 — make_password · 20 минут

make_password(length, has_digit=True, has_upper=True). Устройство простое, без случайностей: первая буква — заглавная A, если has_upper, иначе маленькая a. Последний символ — 1, если has_digit, иначе a. В середине — буквы a, чтобы набрать нужную длину. Длина 0 — пустая строка.

print(len(make_password(8)) == 8)
print(make_password(8) == "Aaaaaaa1")
print(make_password(8, has_digit=False) == "Aaaaaaaa")
print(make_password(8, has_upper=False) == "aaaaaaa1")
print(make_password(0) == "")
Подсказка

Заглавная или маленькая — это выбор из двух, тернарный оператор из дня 5: first = "A" if has_upper else "a". Середина — строку можно умножить на число: "a" * 3 даёт "aaa". Сколько букв в середине, если первая и последняя уже есть?

Длину 0 проверь первой, отдельным if, с return "".

Граница, о которой ты писала требования

Когда все проверки пройдут, вызови print(make_password(1), len(make_password(1))). Какая длина получилась? Совпадает с тем, что ты написала в требованиях? Если нет — это баг в функции, найденный по твоим же требованиям. Запиши его, чинить не обязательно.
