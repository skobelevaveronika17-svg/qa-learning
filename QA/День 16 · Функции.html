Что нужно знать, чтобы начать

def имя(что_на_входе): — так функция объявляется. Код под ней с отступом не выполняется сам — только когда функцию вызывают: имя(данные).

return — что функция отдаёт обратно туда, откуда её вызвали. Остальное разберём на вкладке «Функции».

Сколько искать

Семь проблем. Одна функция из пяти написана правильно — это контрольная. Одна проблема не ломает вывод, но в коде её видно глазами: что-то объявлено и ни разу не использовано.

Готово, когда у каждой находки три части. «Функция не работает» — не находка. «has_digit("Anna1234") печатает False вместо True, потому что…» — находка.

Вот что печатает программа целиком:

True                                          ← print внутри check_length
None                                          ← а это то, что check_length вернула

UnboundLocalError: cannot access local variable 'attempts' ...
1 · check_length печатает, а не возвращает

Что вышло: две строки — True и None — вместо одной.

Почему: внутри функции стоит print(True), а не return True. print показывает на экране, но наружу ничего не отдаёт. Функция без return возвращает None — «ничего».

Последствие: not check_length(...) — это not None, то есть всегда True. Значит, check_password отклонит любой пароль по длине. Отсюда и лишние строки True в выводе: каждый вызов check_length печатает.

2 · has_digit решает по первому символу

Что вышло: False для Anna1234, хотя цифры там есть.

Почему: return сразу выходит из функции — как break, только сильнее. Первый символ «A» не цифра, срабатывает else: return False, и до «1» цикл не доходит.

Правильно — как в has_upper: флаг до цикла, return после цикла. Или return True внутри и return False после цикла, без else.

Это та же ошибка, что «решение внутри цикла» в твоей вчерашней задаче про релиз. Правило то же: цикл просматривает всё, вывод — после.

3 · has_upper — контрольная, написана верно

Флаг до цикла, меняется внутри, return после цикла. Так и надо. Если ты нашла здесь баг — проверь, не придумала ли его.

4 · Аргументы перепутаны местами

Что вышло: «Пароль должен содержать от 8 до 20 символов» вместо OK.

Почему: функция объявлена как check_password(password, email), а вызвана как check_password("anna@test.ru", "Anna1234"). Аргументы раскладываются по порядку: первый — в password, второй — в email. Проверялся адрес почты как пароль.

Как защищаться: именованные аргументы — check_password(password="Anna1234", email="anna@test.ru"). Тогда порядок неважен.

Заметь: даже с правильным порядком вышло бы не OK, а то же сообщение о длине — из-за бага 1. Два бага на одном вызове — частая история.

5 · Параметр email нигде не используется

В выводе этого не видно. Видно только глазами: email принимается и ни разу не участвует в проверках. Либо параметр лишний, либо проверка email забыта. Это вопрос разработчику — как вопрос аналитику в дне 15.

6 · is_blocked блокирует на четвёртой попытке

Что вышло: True при 4 попытках.

Почему: значение по умолчанию limit=4, а по требованию 3.8 блокирует пятая. Это граница — твоя постоянная линия. Три проверки: 4 → False, 5 → True, 6 → True.

7 · Результат check_password выброшен

Что вышло: на экране только True — от print внутри check_length. Самого ответа функции нет.

Почему: функция вызвана, но её результат никуда не положен и не напечатан. return отдаёт значение — а принять его некому. Нужно print(check_password(...)) или result = check_password(...).

8 · add_attempt падает

Что вышло: UnboundLocalError.

Почему: внутри функции стоит присваивание attempts = .... Python решает: значит, attempts — своя, внутренняя переменная этой функции, а не та, что снаружи. А внутренняя ещё пустая — прибавлять не к чему.

Правильно: передать значение внутрь и вернуть новое: def add_attempt(attempts): return attempts + 1, вызов — attempts = add_attempt(attempts).

Как устроена функция

Простыми словами

Функция — рецепт с названием. Записала один раз — дальше пишешь только название и подставляешь продукты. На входе — данные, на выходе — результат.

Зачем — пример

В дне 14 ты проверяла пароль восьми пользователей, и проверка была внутри цикла. А если проверить пароль нужно ещё в регистрации и в смене пароля? Копировать 15 строк трижды — и при изменении правила править в трёх местах. С функцией — пишешь один раз:

def check_password(password):
    if password == "":
        return "Заполните поле"
    if len(password) < 8 or len(password) > 20:
        return "Пароль должен содержать от 8 до 20 символов"
    return "OK"

print(check_password("Anna1234"))   # OK
print(check_password("Ivan123"))    # Пароль должен содержать от 8 до 20 символов
print(check_password(""))           # Заполните поле

Из чего состоит

Почему это важно тестировщику

Автотест проверяет то, что функция вернула. Если функция только печатает, проверить её автоматически нельзя — на экран автотест не смотрит. Баг 1 в охоте — именно такой.

Несколько параметров и значения по умолчанию

def greet(name, greeting="Привет"):
    return f"{greeting}, {name}!"

greet("Анна")                          # Привет, Анна!          — greeting взят по умолчанию
greet("Анна", "Здравствуйте")          # Здравствуйте, Анна!    — по порядку
greet(greeting="Хай", name="Анна")     # Хай, Анна!             — по именам, порядок неважен

Значение по умолчанию — это то, что будет, если аргумент не передали. В охоте limit=4 — неправильное значение по умолчанию: никто не передал limit, и граница съехала незаметно.

Своё и чужое: область видимости

Простыми словами

Переменная, которой присвоили значение внутри функции, — своя у этой функции. Снаружи её не видно. А то, что снаружи, функция может прочитать, но не может изменить простым присваиванием.

def f(x):
    x = x + 1        # это своя x функции — копия значения
    return x

x = 5
print(f(x), x)       # 6 5 — наружная x не изменилась
[Бумага] Правило

Данные — внутрь через параметры, результат — наружу через return. Функция не трогает переменные снаружи. Так её можно проверить отдельно от остальной программы — а значит, написать на неё автотест.

Мостик к pytest

Через три месяца автотест будет выглядеть так:

def test_password_too_short():
    assert check_password("Ivan123") == "Пароль должен содержать от 8 до 20 символов"

Это тоже функция. Внутри — вызов проверяемой функции с тестовыми данными и сравнение результата с ожидаемым. assert — «утверждаю, что это правда»; если нет, тест падает. То есть автотест — это твой тест-кейс, записанный кодом: данные, действие, ожидаемый результат.

Задача 3 — можно ли выпускать · 20 минут

Функция is_release_allowed(bugs) возвращает True, если открытых critical нет, и False, если есть. Сама ничего не печатает.

Проверь её на трёх наборах данных — это и есть мини-автотест:

print(is_release_allowed(bugs) == False)
print(is_release_allowed([]) == True)
print(is_release_allowed([{"id": "BUG-05", "severity": "critical", "status": "closed"}]) == True)

Все три строки должны напечатать True. Если где-то False — нашла баг в своей функции.

Подсказка — вспомни баг 2 из охоты

Можно выйти сразу, как только нашла открытый critical: return False внутри цикла. Но return True — только после цикла, когда просмотрены все. Иначе получится has_digit джуна.

Второй набор — пустой список — граница. Цикл не выполнится ни разу. Что вернёт функция?

Готово, когда вывод задачи 1 совпадает с образцом, задача 2 печатает два словаря, задача 3 — три True. Отступы — по 4 пробела (Ctrl+Alt+L в PyCharm).
