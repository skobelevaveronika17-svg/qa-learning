«Выдаёт 1, т.к. в результатах есть пробел, который не считается»

"failed " и "failed" — разные строки, а count ищет точное совпадение. Лечится нормализацией до подсчёта: strip() из дня 8.

4 · Строка 8 — «Прошло: 2» верно
«Будет 2, так как Passed с большой буквы пишется один раз»

Да. Регистр — тоже часть строки. Нормализация целиком: s.strip().lower(). В задаче 1 по Python ты сделаешь её для всего списка.

5 · Строка 10 — sort() ½
«Выдаёт ошибку, т.к. применена неверная функция» — с объяснением через sorted

Ошибки нет. Программа спокойно печатает По алфавиту: None. Это хуже, чем падение: ничего не красное, а результат неверный.

Почему None: sort() сортирует сам список results и ничего не возвращает. В sorted_results попадает «ничего». Нужен новый отсортированный список — sorted(results). Нужно отсортировать этот же — results.sort() отдельной строкой, без присваивания.

За что половина: фактический результат записан не тот, что выдаёт программа. В баг-репорте «падает» и «показывает пусто» — два разных бага с разной серьёзностью.

6 · Строка 15 — user["Role"] верно
«Роль с большой буквы» (ты записала как строку 14 — сама строка со словарём, обращение строкой ниже)

KeyError: 'Role'. Ключи чувствительны к регистру. Безопасное чтение — user.get("role"): если ключа нет, вернётся None, а не падение.

7 · Строки 18–20 — «копия» ½
«Строка 19 — изменил значение роль на админа»

Строка 19 делает ровно то, что задумано. Баг виден в строке 20: печатается Роль Анны: admin, хотя Анну никто не трогал. Причина — строка 18.

admin = user не создаёт второй словарь. Он даёт тому же самому словарю второе имя. Поменяла через admin — поменялось и у user, потому что это один объект. Копия — admin = user.copy().

Почему это важно тестировщику: тест «вход под админом» испортил общие данные, и следующий тест «вход под пользователем» упадёт — не из-за бага в продукте, а из-за теста. Это постусловие из дня 12, только в коде.

8 · Строки 24–26 — удаление в цикле ½
«Удаляет только один раз указанное значение»

Результат подмечен верно: один failed остался. Но remove тут ни при чём — он вызвался всего один раз, а не два. Вот что происходит на каждом проходе:

Что из этого общее

Три половинки — один и тот же пропуск: ты видишь где, но не дописываешь что именно напечаталось. Это та же структура, что в баг-репорте: шаги, фактический, ожидаемый. С завтрашнего дня находка в охоте записывается тремя частями: строка → что вышло → почему.

[Бумага] strip возвращает, sort меняет

Строка неизменяема: её методы возвращают новую строку, результат нужно присвоить — s = s.strip().

Список изменяем: его методы меняют его самого и возвращают None. Присваивать не надо, иначе получишь находку 5 — x = x.sort() заменит список на None.

Цикл по списку

for status in statuses:
    print(status)

for i, status in enumerate(statuses, start=1):   # нужен и номер
    print(f"TC-{i:03}: {status}")                 # TC-001: passed

{i:03} — число дополняется нулями до трёх знаков. Пригодится для номеров кейсов.

Нужен новый список из старого — пустой до цикла и append внутри. Это накопитель из дня 6 и 13, только копится не число, а элементы. И правило то же: объявляется там, где начинается то, что он копит.

Ссылка, а не копия

a = [1, 2, 3]
b = a            # одно и то же, два имени
c = a.copy()     # новый список
b.append(4)
print(a)         # [1, 2, 3, 4]
print(c)         # [1, 2, 3]
Две ловушки дня — обе из твоей охоты
  • b = a не копирует. Ни список, ни словарь. Копия — .copy().
  • Не удаляй из списка, по которому идёшь. Цикл перешагнёт через соседний элемент. Собирай новый список.

Словари, множества, кортежи

20 минут

[Бумага] Что такое словарь

Набор пар «ключ — значение» в фигурных скобках. Ищет не по номеру, а по имени. Ключи уникальны, значения — любые.

user = {"email": "anna@test.ru", "password": "Anna1234", "role": "user"}

user["email"]               # "anna@test.ru"
user["phone"]               # KeyError
user.get("phone")           # None, без падения
user.get("phone", "нет")    # "нет" — значение по умолчанию

user["role"] = "admin"      # изменить
user["attempts"] = 0        # добавить: ключа не было — появится
del user["attempts"]        # удалить
"email" in user             # True — in проверяет КЛЮЧИ, не значения
len(user)                   # 3 — число пар
Запись по несуществующему ключу не падает

user["Role"] = "admin" молча создаст второй ключ рядом с "role". Опечатка в ключе при чтении — громкий KeyError, при записи — тихий баг. Громкий лучше: его хотя бы видно.

Три способа пройти по словарю

for key in user:                   # ключи
    print(key)
for value in user.values():        # значения
    print(value)
for key, value in user.items():    # пары — нужен чаще всего
    print(f"{key}: {value}")

Список словарей — это уже JSON

users = [
    {"email": "anna@test.ru", "role": "user",  "active": True},
    {"email": "ivan@test.ru", "role": "admin", "active": False},
]
for u in users:
    print(u["email"], u["role"])
Мостик к этапу 5

Ответ сервера на «дай список пользователей» выглядит ровно так. Автотест по API — это обращения к ключам и сравнение значений: пришёл ли "role", равен ли он "admin", сколько элементов в списке. Поэтому словари — фундамент, а не очередная тема.

Типичные ошибки этой задачи
  • Флаги объявлены до внешнего цикла. Тогда True от Анны переедет к Ольге. Флаги сбрасываются для каждого пароля — значит, внутри внешнего цикла. Накопитель объявляется там, где начинается то, что он копит.

  • Несколько if вместо elif — Катя получит три сообщения.
