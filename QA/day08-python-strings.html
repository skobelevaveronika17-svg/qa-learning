Как устроена строка

15 минут

Строка

Последовательность символов. Каждый символ имеет номер — индекс. Нумерация идёт с нуля.

СимволPython
Индекс012345
С конца-6-5-4-3-2-1
word = "Python"

print(word[0])     # P — первый символ
print(word[5])     # n — последний
print(word[-1])    # n — последний, короче и надёжнее
print(len(word))   # 6 — количество символов

Отрицательные индексы удобны тем, что не нужно знать длину: word[-1] — всегда последний символ, какой бы длины ни была строка.

Ловушка: индекс на единицу больше длины

В строке из 6 символов последний индекс — 5, потому что счёт с нуля. Обращение к word[6] даёт IndexError. Та же ошибка на единицу, что и в range, и в границе 4999 — третья её форма за неделю.

Срезы

Можно взять не один символ, а кусок:

word = "Python"

print(word[0:3])   # Pyt — с 0 по 3, тройка не включается
print(word[2:])    # thon — с 2 и до конца
print(word[:4])    # Pyth — с начала по 4
print(word[-3:])   # hon — последние три
Правая граница снова не входит

[0:3] берёт символы 0, 1, 2. Ровно как range(0, 3). Логика в Python везде одна: левая граница включается, правая нет. Запомнишь один раз — будет работать и для срезов, и для циклов.

Перебор символов

Строку можно пройти циклом, ты это уже делала на дне 6:

for letter in "кот":
    print(letter)

Это понадобится сегодня в задаче про пароль: чтобы проверить «есть ли в пароле хотя бы одна цифра», нужно пройти по символам и посмотреть каждый.

В тетрадь

Таблицу индексов для слова Python — с прямыми и отрицательными. И правило: левая граница среза входит, правая нет.

Почему методы не меняют строку

15 минут. Самая важная вкладка дня

Строки неизменяемы

Созданную строку нельзя изменить. Любой метод, который «меняет» строку, на самом деле создаёт новую и возвращает её. Исходная остаётся нетронутой.

Отсюда правило, из которого следует всё остальное:

name = "  anna  "

name.strip()          # результат вычислен и выброшен
print(name)           # "  anna  " — ничего не изменилось

name = name.strip()   # результат сохранён обратно в переменную
print(name)           # "anna"
Почему на этом спотыкаются все

Потому что запись name.strip() читается как приказ: «имя, очистись». А на самом деле это вопрос: «как выглядело бы имя, если его очистить?» Ответ приходит и, если его никуда не положить, теряется.

Правило на каждый день: увидела метод строки без знака = слева — почти наверняка баг.

Попытка изменить символ напрямую тоже не сработает, но здесь Python хотя бы честно ругается:

word = "кот"
word[0] = "р"        # TypeError: строка не поддерживает присваивание по индексу

Чтобы получить «рот», нужно собрать новую строку: word = "р" + word[1:]

Зачем язык так устроен

Неизменяемость даёт предсказуемость. Если ты передала строку в функцию, можно быть уверенной, что функция её не испортила: вернуть она может что угодно, но твоя переменная останется прежней. Для тестировщика это важно: строки не меняются «где-то там» сами по себе.

На карточку

Что вернёт name.strip(), если не присвоить результат? — Ничего не изменится: строки неизменяемы, метод возвращает новую строку, а старая остаётся. Нужно name = name.strip().

В errors-log.md

«Метод строки без присваивания не меняет переменную. Ошибки нет, поведение неверное.» Эта строка сэкономит тебе часы на ближайшие месяцы.

Заодно: .strip() убирает не только пробелы, но и переводы строк и табуляцию — всё, что считается пробельными символами. Это как раз то, что прилетает при копировании из Word или Excel.

Зачем это тестировщику: нормализация

Сравнение строк в Python чувствительно к регистру: "Anna" == "anna" даёт False. Поэтому перед сравнением логинов и адресов почты их приводят к единому виду — обрезают края и опускают регистр. Это называется нормализацией.

entered = "  Anna@Mail.RU  "
saved = "anna@mail.ru"

print(entered == saved)                          # False — не войдёт
print(entered.strip().lower() == saved)          # True — войдёт

Здесь два метода вызваны подряд: сначала .strip() вернул строку, у неё тут же вызвали .lower(). Так можно — это называется цепочкой вызовов.

Готовый тест-кейс на любую форму входа

Ввести логин с пробелом в начале и в другом регистре. Если система не пускает — баг: пользователь не виноват, что скопировал адрес с пробелом. На собеседовании это хороший пример «какой баг вы находили».

На карточку

Что такое нормализация строки и зачем нужна? — Приведение к единому виду перед сравнением: обрезать пробелы, опустить регистр. Иначе пользователь с лишним пробелом не войдёт в свой аккаунт.

Методы: поиск, проверка, разбиение

20 минут

Есть ли что-то в строке

email = "anna@mail.ru"

print("@" in email)                # True — самый простой способ
print(email.startswith("anna"))    # True
print(email.endswith(".ru"))       # True
print(email.count("a"))            # 3 — сколько раз встречается
print(email.find("@"))             # 4 — индекс первого вхождения, -1 если нет

Оператор in ты уже знаешь по циклам — там он означал «из последовательности». Со строками он проверяет вхождение и возвращает True или False.

Из чего состоит строка

МетодTrue, если строка состоит изПример TrueПример False
.isdigit()только цифр"123""-5", "3.5", ""
.isalpha()только букв"anna""anna1", "an na"
.isalnum()букв и цифр"anna1""anna_1"
.isspace()только пробельных символов" """, "a "
isdigit врёт чаще, чем кажется

"-5".isdigit() — False, минус не цифра. "3.5".isdigit() — False, точка не цифра. "".isdigit() — False, пустая строка ничем не состоит.

То есть проверка «пользователь ввёл число» через .isdigit() отсекает отрицательные и дробные. Для целых положительных — годится, для остального нужны другие способы.

Три пробела — не пустая строка

" " == "" даёт False, а len(" ") даёт 3. Именно поэтому валидатор с первой вкладки пропускал пробелы. Проверять на пустоту нужно после .strip() — тогда три пробела превратятся в пустую строку и отвалятся.

Замена и разбиение

phone = "+375 (29) 123-45-67"

clean = phone.replace(" ", "")     # убрать все пробелы
print(clean)                        # +375(29)123-45-67

text = "хлеб молоко сыр"
words = text.split()                # разбить на части по пробелам
print(words)                        # ['хлеб', 'молоко', 'сыр']
print(len(words))                   # 3 — количество слов

date = "16.09.2026"
parts = date.split(".")             # разбить по точке
print(parts)                        # ['16', '09', '2026']

.split() возвращает список — новый тип данных. Подробно списки будут отдельным днём, сегодня достаточно знать: по нему можно ходить циклом и считать длину через len().

split() и split(" ") — разные вещи

Без аргумента .split() считает любую группу пробелов одним разделителем и игнорирует края. С аргументом .split(" ") режет строго по каждому пробелу, и два пробела подряд дадут пустой элемент в середине.

На строке "a  b": первый вариант даст 2 слова, второй — 3, одно из которых пустое. Классический источник неверного подсчёта слов.

В тетрадь

Таблицу методов одним списком: strip, lower, upper, replace, split, find, startswith, endswith, isdigit, isalpha. Без подробностей — просто чтобы знать, что искать. Гуглить синтаксис нормально, не знать о существовании метода — нет.

  1. Получить пароль. Не обрезать края — в пароле пробел запрещён, и если его молча убрать, пользователь не поймёт, почему пароль не подходит.

Подсказка 1 — мягкая
