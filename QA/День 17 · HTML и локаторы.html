Семь проблем формы

15 минут. После охоты

1 · Поле пароля показывает пароль

Что вышло: введённые символы видны на экране.

Почему: у поля type="text" вместо type="password". Пароль увидит любой, кто стоит рядом или смотрит запись экрана. Баг безопасности, и одновременно автотест не найдёт поле по [type="password"].

2 · Два элемента с одним id

Что вышло: у email и у пароля id="field".

Почему плохо: id по правилам HTML должен быть уникальным на странице. Локатор #field найдёт два элемента, и автотест введёт пароль не туда — или возьмёт первый попавшийся. Проверь: в Elements нажми Ctrl+F и введи #field — справа будет «1 of 2».

3 · Подписи не связаны с полями

Что вышло: клик по слову «Email» ничего не делает. А клик по «Запомнить меня» ставит галочку.

Почему: у подписи галочки есть for="cb-…" — она связана с полем. У подписей Email и Пароль атрибута for нет. Для пользователя это неудобство, а для экранных читалок у незрячих — поле без названия. Это доступность — тоже вид тестирования.

4 · «Войти» — не кнопка

Что вышло: Tab пропускает «Войти», Enter её не нажимает. Нажать можно только мышью.

Почему: это <div> с обработчиком клика, оформленный под кнопку. Настоящая кнопка — <button>: она получает фокус и нажимается с клавиатуры. Автотесту тоже сложнее: локатор button её не найдёт.

Тебе как дизайнеру: на макете они одинаковые. Разница — только в разметке. Поэтому тестировщик смотрит и в разметку тоже.

5 · id галочки меняется при каждой загрузке

Что вышло: id="cb-48213", после обновления — другое число.

Почему плохо: такой id генерирует фреймворк. Локатор #cb-48213 сработает один раз и сломается при следующем запуске. Это частая причина флакающих тестов — карточка B.

6 · Ссылка «Забыли пароль?» ведёт никуда

Что вышло: href="#" — клик просто прокручивает страницу наверх.

Почему: функциональный баг — восстановления пароля нет. Хотя тут есть оправдание: требования к восстановлению на уточнении. Это ты сама записала в тест-план.

7 · У логотипа нет alt

Что вышло: у <img> нет атрибута alt.

Почему плохо: если картинка не загрузится, на её месте пусто. Экранная читалка не знает, что это. Тоже доступность.

Контрольный · data-testid у поля email — это хорошо

data-testid="login-email" — атрибут, который разработчики добавляют специально для автотестов. Он не меняется при редизайне, не зависит от стилей и уникален. Лучший локатор, какой бывает. Если ты записала его в баги — посмотри теорию.

Как устроена страница и как найти элемент

40 минут

Простыми словами

HTML — это дерево вложенных элементов, как слои и фреймы в Figma. CSS-селектор — способ сказать «вот этот элемент» по его признакам: тегу, id, классу, атрибуту. Автотест находит элементы ровно этими селекторами.

Элемент: тег, атрибуты, содержимое

<input type="email" id="email" class="field" data-testid="login-email">
 │      │            │          │             │
 тег    атрибут      атрибут    атрибут       атрибут для автотестов
<button class="btn primary">Войти</button>
                          └────┘ └─────┘
                    содержимое   закрывающий тег

У input нет закрывающего тега и нет содержимого — только атрибуты. У button, a, div — есть.

Вложенность — дерево

<form id="login">
    <div class="fld">
        <label for="email">Email</label>
        <input id="email">
    </div>
    <button>Войти</button>
</form>

form — родитель. div и button — его дети. input — внук формы и ребёнок div. В Figma это выглядело бы как фрейм с вложенными группами — Elements в DevTools показывает ровно это дерево.

Самая частая ошибка — лишний пробел: input .field — это «элемент с классом field внутри input», такого не бывает. А input.field — «input с классом field».

Как проверить селектор

  1. F12 → вкладка Elements.
  2. Ctrl+F (на Mac — Cmd+F). Внизу появится строка поиска.
  3. Вставь селектор. Справа — счётчик: «1 of 1» значит найден ровно один элемент. Он подсветится.

Какой локатор хороший

Простыми словами

Хороший локатор находит ровно один элемент и не ломается, когда меняют дизайн.

Порядок выбораПримерПочему
1. data-testid[data-testid="login-email"]создан для тестов, не меняется
2. id, если постоянный#emailуникальный, короткий
3. name или атрибут по смыслу[name="password"]связан с логикой, а не с видом
4. класс плюс тегbutton.primaryможет сломаться при редизайне
Плохие локаторы
  • Цепочка по положению: div > div > div:nth-child(3) > input — сломается, как только добавят один блок.
  • Динамический id: #cb-48213 — другой при каждой загрузке.
  • Класс оформления: .blue-big — дизайнер поменяет цвет, тест упадёт.

Функции для локаторов

60 минут · файл python/day17_locators.py

Сегодня сделаем на Python маленькую модель того, что делает браузер, когда ищет элемент по селектору. Страница — это список словарей, каждый словарь — элемент с атрибутами.

0. Разобранный пример

def by_tag(tag):
    return tag

def count_tags(elements):
    counts = {}
    for e in elements:
        t = e["tag"]
        counts[t] = counts.get(t, 0) + 1
    return counts

page = [{"tag": "input"}, {"tag": "input"}, {"tag": "button"}]
print(by_tag("input"))       # input
print(count_tags(page))      # {'input': 2, 'button': 1}
Проходtcounts.get(t, 0)counts после
1"input"0 — ключа нет{'input': 1}
2"input"1{'input': 2}
3"button"0 — ключа нет{'input': 2, 'button': 1}

Это словарь-счётчик в одну строку через get с нулём — без if/else. Выбирай один способ, не смешивай.

Данные для всех задач — скопируй в начало файла:

elements = [
    {"tag": "input", "id": "email", "type": "email", "class": "field", "data-testid": "login-email"},
    {"tag": "input", "id": "password", "type": "password", "class": "field"},
    {"tag": "input", "type": "checkbox", "class": "check"},
    {"tag": "button", "id": "submit", "type": "submit", "class": "btn primary"},
    {"tag": "a", "class": "link", "href": "#"},
]

Задача 1 — собрать селектор · 15 минут

Три функции, каждая возвращает строку-селектор:

  • by_id(element_id) → #email
  • by_class(name) → .field
  • by_attr(attr, value) → [type="password"] — с двойными кавычками вокруг значения

Проверки — все должны напечатать True:

print(by_id("email") == "#email")
print(by_class("field") == ".field")
print(by_attr("type", "password") == '[type="password"]')
print(by_attr("data-testid", "login-email") == '[data-testid="login-email"]')
Подсказка — кавычки

Внутри строки нужны двойные кавычки — значит, саму f-строку пиши в одинарных: f'[{attr}="{value}"]'.

Задача 2 — найти элементы · 25 минут

find_by_attr(elements, attr, value) возвращает список id всех элементов, у которых атрибут attr равен value. Если у найденного элемента нет id — вместо него в список кладётся строка "без id".

print(find_by_attr(elements, "class", "field") == ["email", "password"])
print(find_by_attr(elements, "type", "checkbox") == ["без id"])
print(find_by_attr(elements, "name", "login") == [])
Подсказка — у элементов разные атрибуты

У галочки нет id, ни у кого нет name. e["name"] упадёт с KeyError. Что вернёт e.get("name"), если ключа нет? А e.get("id", "без id")?

Третья проверка — граница: ничего не найдено. Функция должна вернуть пустой список, а не упасть.

Задача 3 — уникален ли локатор · 15 минут

Хороший локатор находит ровно один элемент. Функция is_unique(elements, attr, value) возвращает True, если нашёлся ровно один элемент. Используй внутри find_by_attr — не пиши поиск заново.

print(is_unique(elements, "id", "email") == True)
print(is_unique(elements, "class", "field") == False)
print(is_unique(elements, "name", "login") == False)
Со звёздочкой

У кнопки class="btn primary" — два класса. find_by_attr(elements, "class", "btn") её не найдёт: строки не равны. Напиши has_class(element, name), которая вернёт True, если name — один из классов элемента. Вспомни split() из дня 8.

Правило дня — запусти проверки до того, как присылать

Все проверки уже написаны в задании. Скопируй их как есть, запусти и пришли вывод вместе с кодом. Если где-то False — ищи баг сама, это и есть работа тестировщика. Не убирай == ... из проверок.

Готово, когда все десять проверок печатают True и ты прислала код вместе с выводом.
